# 后台模拟器与 ADB 调试

本项目可以直接使用 Android SDK 的 Emulator、ADB 和 Gradle 完成构建、运行、截图与测试，无需启动 Android Studio。

## 启动与日常操作

在项目根目录执行（Python 3，无额外依赖）：

```powershell
python scripts/android_emulator.py --sdk D:/Android/Sdk start
python scripts/android_emulator.py --sdk D:/Android/Sdk status
python scripts/android_emulator.py --sdk D:/Android/Sdk install
python scripts/android_emulator.py --sdk D:/Android/Sdk launch
python scripts/android_emulator.py --sdk D:/Android/Sdk capture --output artifacts/emulator/home.png
python scripts/android_emulator.py --sdk D:/Android/Sdk logs
python scripts/android_emulator.py --sdk D:/Android/Sdk ui
python scripts/android_emulator.py --sdk D:/Android/Sdk stop
```

脚本默认使用 `Pixel_10_Pro_Fold` 和 `emulator-5556`。可在子命令前传 `--serial emulator-5554`，在 `start` 后传 `--avd 名称`。SDK 也可通过 `ANDROID_HOME` 或项目的 `local.properties` 提供。

后台启动参数为 `-no-window -no-audio -no-boot-anim -no-snapshot -gpu host -feature -Vulkan`，Windows 使用隐藏进程，不弹出模拟器窗口。日志位于 `artifacts/emulator/`。已有相同序列号的在线设备时复用该设备；启动仍在进行时先看日志和进程状态，再决定后续操作。

更换渲染参数时先执行 `stop`，确认旧实例退出后再执行 `start`；在线实例的启动参数不会因再次调用 `start` 而变化。

这台机器的后台 `auto` 渲染实际选中了 SwiftShader/Lavapipe，运行 2K 折叠屏时出现资源占用升高、ADB 设备通道失去响应；主机 GPU 通过 `--gpu host` 显式选择。其他环境可试 `--gpu software`，并相应降低模拟器分辨率。

反复切换高分辨率显示后，主机 GPU 日志还出现过 `Failed to import external memory object`、`bad color buffer handle`，伴随模拟器系统崩溃。默认关闭 Vulkan 互操作，使用 GLES 渲染；需要开启时传 `start --vulkan`。遇到异常先读取模拟器日志、`logcat -b crash` 和 `dumpsys activity exit-info`，确认进程终态及原因后再处理。

## 构建和安装

```powershell
$env:GRADLE_USER_HOME='C:/Users/Administrator/.gradle'
.\gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest --console=plain
```

应用 APK：`app/build/outputs/apk/debug/app-debug.apk`；测试 APK：`app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk`。

## 直接使用 ADB

每次指定序列号，避免对连接的其他设备执行命令：

```powershell
$adb='D:/Android/Sdk/platform-tools/adb.exe'
& $adb devices -l
& $adb -s emulator-5556 shell am start -W -n com.luna.music/com.example.seteasecloudmusic.feature.main.MainActivity
& $adb -s emulator-5556 shell input tap 200 300
& $adb -s emulator-5556 shell input swipe 600 1700 600 500 400
& $adb -s emulator-5556 shell input keyevent KEYCODE_BACK
& $adb -s emulator-5556 shell uiautomator dump /sdcard/window.xml
& $adb -s emulator-5556 shell cat /sdcard/window.xml
& $adb -s emulator-5556 logcat -d -v threadtime
& $adb -s emulator-5556 logcat -b crash -d
& $adb -s emulator-5556 shell dumpsys activity exit-info com.luna.music
```

截图脚本以二进制接收 `adb exec-out screencap -p`，避免 PowerShell 旧版重定向破坏 PNG。折叠屏的默认物理屏可能是已熄灭的内屏，脚本从 `dumpsys display` 选择 `state ON` 的物理显示器；需要指定时传 `capture --display-id ID`。可用 `adb -s emulator-5556 shell dumpsys SurfaceFlinger --display-id` 查询物理 ID。截图生成后直接打开 PNG 查看效果。

## 折叠、旋转和大字号

先查询本机虚拟设备提供的状态：

```powershell
& $adb -s emulator-5556 shell cmd device_state print-states
& $adb -s emulator-5556 emu sensor status
```

本机 Pixel Fold 使用 `0` 合拢、`1` 半折叠、`2` 展开。姿态与实际面板一起切换：

```powershell
# 合拢外屏
& $adb -s emulator-5556 emu fold
& $adb -s emulator-5556 shell cmd device_state state 0
# 展开内屏
& $adb -s emulator-5556 emu unfold
& $adb -s emulator-5556 emu sensor set hinge-angle0 180
& $adb -s emulator-5556 shell cmd device_state state 2
# 半折叠；再旋转成横向可观察上下分屏
& $adb -s emulator-5556 emu sensor set hinge-angle0 90
& $adb -s emulator-5556 shell cmd device_state state 1
& $adb -s emulator-5556 shell cmd window user-rotation lock 1
```

切屏后必要时唤醒并关闭无密码锁屏：`shell input keyevent KEYCODE_WAKEUP`、`shell wm dismiss-keyguard`。单独覆盖 `device_state` 可能留下熄灭的活动面板，应同时使用 `emu fold/unfold`。

外屏启动器可能固定竖屏。检查横屏时先启动本应用，再锁定旋转，并通过 `shell dumpsys window displays` 中的 `DisplayFrames` 核对实际方向；矩阵脚本已包含这一步，截图测试还会再次断言窗口宽高和折痕。

大字号：`shell settings put system font_scale 1.5`。窗口缩小：`shell wm size 1240x1550`。检查完成后恢复原值；自动矩阵脚本会记录并恢复字号、尺寸、旋转和姿态覆盖；测试前会为调试模拟器上的应用授予媒体读取和通知权限，避免权限弹窗遮住本地音乐夹具。

物理内外屏切换可能清除过早设置的尺寸覆盖。矩阵脚本会在唤醒面板、启动应用之后重复应用缩小尺寸，并要求 `DisplayFrames` 的真实宽高与方向连续稳定三次，再启动设备测试。

## 全页面矩阵

```powershell
python scripts/verify_foldable_layouts.py --adb D:/Android/Sdk/platform-tools/adb.exe
# 仅验证外屏、书本和桌面姿态
python scripts/verify_foldable_layouts.py --adb D:/Android/Sdk/platform-tools/adb.exe --scenarios outer,book,tabletop
# 设备故障后补跑：源码、检查脚本、测试源码、两份 APK 与页面范围全部一致时复用已通过配置
python scripts/verify_foldable_layouts.py --adb D:/Android/Sdk/platform-tools/adb.exe --resume
# 仅复验真实导航和播放器，并保存到独立目录
python scripts/verify_foldable_layouts.py --adb D:/Android/Sdk/platform-tools/adb.exe --pages chrome,native_music --output artifacts/glass/focused
# 复用已在线的后台模拟器，仅检查真实播放页和歌词控制区
python scripts/verify_foldable_layouts.py --adb D:/Android/Sdk/platform-tools/adb.exe --serial emulator-5554 --pages native_music --output artifacts/player/focused
```

截图、窗口/折痕元数据、测试日志和 SHA256 位于 `artifacts/foldable/verified/`。报告同时记录生产源码、检查脚本/设备测试源码及两份 APK 的哈希。截图先等待 Compose 切换动画与 Android 绘制完成，歌词页采集的是实际切换后的画面。这些运行产物已加入 Git 忽略。测试通过本地虚构封面和歌曲填充实际页面，不发起播放或登录操作；账号页沿用设备现有登录态，因此截图中可能包含设备账号信息，分享前检查。
