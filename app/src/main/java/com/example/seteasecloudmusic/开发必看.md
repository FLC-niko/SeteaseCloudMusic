# SeteaseCloudMusic 开发必看

> 仿 Apple Music 风格 Android 音乐播放器 · 后端接口：`nimabi520/api-enhanced`（网易云音乐 API）
>
> 最后更新：2026-09-02

---

## 一、技术栈

| 领域 | 选型 |
|------|------|
| 开发语言 | Kotlin |
| UI 框架 | Jetpack Compose + Material3 |
| 架构模式 | 分层架构 + 按功能分包（Feature-based Clean Architecture） |
| 网络请求 | Retrofit 3.0 + OkHttp2/O+Kotlin Coroutines & Flow |
| 媒体播放 | AndroidX Media3 (ExoPlayer) + MediaSessionService |
| 图片加载 | Coil Compose 2.7（全局 ImageLoader，200MB 磁盘缓存） |
| 特效 | Liquid Glass（kyant0/backdrop + shapes） |
| 依赖注入 | **Hilt**（`@HiltAndroidApp` / `@AndroidEntryPoint` + 分模块 Module） |
| 歌词进阶 | amll（Apple Music-like Lyrics）WebView 渲染方案 |

## 五、Apple Music UI 设计灵魂要点

实现以下效果时需要的核心技术：

| 效果 | 实现方案 |
|------|---------|

| **分段式导航栏** | 已实现的 `GlassSlider` 拖拽弹性 + squircle 圆角 |

### 鉴权机制

1. 登录成功后后端返回 `Set-Cookie`，其中 `MUSIC_U` 是核心凭证
2. 后续所有需要登录态的请求，由 `AuthInterceptor` 自动在 Header 附加 `Cookie: MUSIC_U=xxx`
3. Cookie 持久化在 SharedPreferences；**注意**：部分登录接口不返回 `Set-Cookie`，cookie 在 JSON body 的 `cookie` 字段中，拦截器已在无 Set-Cookie 时从响应体兜底提取保存（见 dev 备忘）
4. 401/登录失效时触发 `refreshLogin`，失败后引导用户重新登录

## 八、编码规范速查

- **分层规则**：`data` → `domain` → `presentation`，依赖方向单向向内
- **Feature 内自治**：每个 feature 包含独立的 data/domain/presentation，**并有独立的 `di/` Hilt 模块**
- **core 下沉共享**：网络、播放器、核心模型、缓存、设置放 `core/`，不混入业务逻辑
- **依赖注入**：全局 Retrofit Service 在根 `di/NetworkServiceModule`，Repository/UseCase 在 `core/di/` 与各 feature `di/` 绑定
- **UseCase 单一职责**：每个 UseCase 只做一件事，通过 `operator fun invoke()` 调用
- **DTO 与领域模型分离**：`data/model/` 放 API 响应 DTO，`domain/model/` 放纯净领域模型
- **状态管理**：ViewModel 持有 `MutableStateFlow<UiState>`，Compose 用 `collectAsStateWithLifecycle()` 收集
- **播放性判断**：优先 `privilege` 字段判断能否播放（勿仅按 `fee == 1` 一刀切），避免误判 VIP 可播歌曲
- **推荐数据结构**：`/recommend/songs` 响应比最小 DTO 更丰富（含 `recommendReasons`、`mainTitle`/`additionalTitle` 等），解析注意容错扩展
